# OnRobot 2FG14 integration

## Goal

Port and simplify the tested 2FG14 Compute Box driver while preserving width, force, speed, object-detection, and recovery behavior.

## Inputs

- Shared gripper contract
- Current `OnRobot2FG14` code and tests
- Approved small-tray picking profile
- 2FG14 description and mount

## Outputs

- `onrobot_2fg14` profile
- Driver plugin over the supported Compute Box protocol
- Width/force/speed and internal/external-grip capabilities
- Status and object-detection policy
- Simulator joint/force model
- Characterization and hardware tests

## Work

1. Characterize connection, auto-limit query, device identity, command timeout, motion start, width reporting, force limits, object detection, and disconnect behavior from the current driver.
2. Store host, port, tool index, device ID, finger geometry, stroke, force bounds, default speed, and commissioning data in the tool profile.
3. Expose open, close, and grip with explicit width, force, speed, direction, wait, timeout, and require-object options.
4. Keep the returned width and object-detection evidence in the result. Reaching requested width without detected object is a grasp failure when require-object is true.
5. Model finger joints, width feedback, collision, commanded speed/force, and object contact in both simulators.
6. Port approved small-tray values as migrated data, not driver defaults. Verify their units and revision binding.
7. Test empty close, obstructed close, successful external grip, timeout, disconnect, stop, reconnect, and width-tolerance verification.

## Interfaces and data

- Shared Gripper plugin
- Compute Box transport
- Position-gripper facade
- Gripper-specific grasp profile fields

## Boundaries

- Does not place object-specific width/force settings in driver code
- Does not hide connection or auto-limit failures
- Does not support unverified custom fingers

## Failure behavior

- Raise distinct connection, identity, range, command, timeout, empty-grip, width-mismatch, and stop errors.
- Lost connection while holding reports uncertain tool state and requires explicit recovery.

## Acceptance

- Existing driver characterization cases pass through the new contract.
- Simulator width and object-detection behavior pass shared tests.
- Small-tray profile round-trips with exact units and tolerances.
- Installed driver verifies identity and limits before first command.
- No task imports the transport implementation.

## Parallel work

Runs alongside vacuum tool packets.
