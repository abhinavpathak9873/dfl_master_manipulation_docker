# OnRobot 2FG14 integration

## Goal

Support the 2FG14's width/force behavior, geometry, feedback, and verification
needs as a first-class parallel gripper.

## Task-script payoff

A task can call `close(force=..., expected_width=...)` and use the returned width,
force, and success evidence in ordinary retry logic.

## Work

1. Characterize current `OnRobot2FG14` code, communication, commands, state,
   units, timeouts, and error handling against installed behavior.
2. Add mount, TCP, fingers, collision geometry, payload, width range, and
   calibration/commissioning facts.
3. Implement open, width/close, force, stop, status, timeout, and useful result
   mapping with explicit units.
4. Keep expected object width/tolerance and grasp verification in the task or
   object grasp profile.
5. Model finger motion/contact in Gazebo and Genesis with honest force limits.
6. Test no-object full close, correct-object stop, early/wrong stop, obstruction,
   timeout, disconnect, cancel, and release.
7. Keep vendor/backend access available for diagnostics and specialized commands.

## Acceptance

- Requested/final width and force are clear and correctly scaled.
- The canonical failed-grasp loop can decide from result fields.
- Collision/TCP/finger geometry follows commanded state in both simulators.
- Real commissioning verifies safe open/close/stop before task trials.

## Non-goals

Automatic object inference, grasp planning, or a generic parallel-gripper
framework beyond proven shared behavior.
