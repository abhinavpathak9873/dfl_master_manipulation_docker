# VGP20 integration

## Goal

Add the OnRobot VGP20 as its own high-payload vacuum tool with correct geometry, control, feedback, and grasp-profile requirements.

## Inputs

- Shared gripper contract
- Official VGP20 documentation and installed integration details
- Doosan/OnRobot communication path
- Simulator suction contract

## Outputs

- `onrobot_vgp20` profile
- Description, mount, TCP, payload, and collision assets
- VGP20 driver plugin
- Vacuum/channel/status configuration
- Simulator model and contract fixtures
- Commissioning and limitation report

## Work

1. Record the supported communication path, device identity, channels, vacuum units, payload limits, release behavior, status fields, and vendor timeouts from first-party documentation and installed hardware.
2. Build the tool description from authoritative dimensions and the actual mounting bracket. Keep large collision geometry conservative and separate from visual mesh.
3. Map public grip/release/status/stop operations to VGP20 commands. Preserve channel-level diagnostics when the hardware exposes them.
4. Require VGP20-specific grasp profiles; never reuse VGC10 anchors based only on both tools being vacuum grippers.
5. Implement simulator contact/seal behavior for configured cup geometry and object materials within v1's rigid opaque scope.
6. Test porous-object failure representation, partial channel failure, disconnect, timeout, pressure loss, release, and restart.
7. Qualify only mounted real combinations while leaving all robot combinations available in simulation.

## Interfaces and data

- Shared Gripper plugin
- VGP20 vendor transport
- Tool/grasp profile binding
- Simulated channel and held-object state

## Boundaries

- Does not invent vendor feedback absent from the installed API
- Does not claim real qualification without the device
- Does not model unrestricted porous or deformable materials

## Failure behavior

- Connection, device-ID, vacuum-achievement, channel, timeout, and object-loss failures remain distinct.
- Unknown status blocks a success result.

## Acceptance

- Description and profile validate for M1013 and H2515.
- Shared tests pass in both simulators.
- Driver reports measured feedback or declares the exact unavailable capability.
- Object-loss injection is visible before subsequent lift success.
- Hardware report records commands, state, stop, and release when access exists.

## Parallel work

Runs with other tool packets.

## What this module needs from me

Facts: VGP20 availability, mount, controller/Compute Box endpoint, and channel configuration. If no hardware is available, real qualification remains explicitly pending.
